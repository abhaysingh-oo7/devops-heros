## Task 1: Soft Link vs. Hard Link

### My understanding :

* **Inode:** I think of an **inode** as the actual memory ID or "house" where the file's data and information are stored. The file name is like the nameplate on the door.
* **Hard Link:** A **hard link** is like having a second nameplate pointing to the **exact same house (same inode)**. Even if the original file is deleted, the data is still safe because the hard link points to the same inode.
* **Soft Link (Symlink):** A **soft link** is like a shortcut, similar to a Windows shortcut. It points to the *original file name/path*. If the original file is deleted, the shortcut becomes broken, also called a **dangling link**.

### Commands I practiced :

```bash
# 0. Create a directory for this task
mkdir task1 && cd task1

# 1. Create a dummy file
echo "Hello DevOps" > original.txt

# 2. Create a Hard Link
ln original.txt hardlink.txt

# 3. Create a Soft Link
ln -s original.txt softlink.txt

# 4. Check the inode numbers
# Notice that original.txt and hardlink.txt have the same inode number
ls -li

# 5. Delete the original file
rm original.txt

# Check what happens:
cat hardlink.txt   # Still prints "Hello DevOps"
cat softlink.txt   # Gives an error because the original file is deleted
```

### Quick Comparison Table (For Interview)

| Feature                               | Hard Link                          | Soft Link (Symbolic)          |
| :------------------------------------ | :--------------------------------- | :---------------------------- |
| **What it is**                        | Directly points to the same inode. | Points to the file path/name. |
| **Command**                           | `ln file link`                     | `ln -s file link`             |
| **If original is deleted**            | Data remains accessible.           | Link becomes broken.          |
| **Across different disks/partitions** | No                                 | Yes                           |
| **Can link directories**              | No                                 | Yes                           |

## Task 2: `adduser` vs. `useradd`

### My understanding :

* **`useradd` (Low-level / Raw):** A basic command used to create a user. It provides more control through command-line options, but things like the home directory, password, and other settings may need to be configured separately.
* **`adduser` (Friendly / Recommended on Ubuntu):** A more user-friendly interactive utility. It guides us step-by-step, asks for the required information, creates the home directory, and sets up the account with suitable defaults.

> **Ubuntu Preference:** For manually creating a normal user, I would prefer **`adduser`** because it is easier to use and helps avoid missing important account settings.

### Commands I practiced :

```bash
# 1. Create a test user interactively
sudo adduser testdevops

# 2. Add the user to the sudo (admin) group
sudo usermod -aG sudo testdevops

# 3. Verify the user ID, groups, and home directory
id testdevops
ls -ld /home/testdevops

# 4. Delete the test user and its home directory after testing
sudo userdel -r testdevops
```

## Task 3: `journalctl` (System & Service Logs)

### My understanding :

I think of `journalctl` as a **black-box flight recorder for Linux**. It collects and displays logs generated by the operating system, kernel, and background services such as Docker, Nginx, or SSH.

It is useful for checking system activity, finding errors, and troubleshooting services.

### Commands I practiced :

```bash
# 1. View the recent 20 logs for the SSH service
sudo journalctl -u ssh -n 20 --no-pager

# 2. View SSH logs live in real-time
# Press Ctrl+C to exit
sudo journalctl -u ssh -f

# 3. View system errors only
# Priority = error
sudo journalctl -p err -n 10 --no-pager

# 4. View logs from the current boot
sudo journalctl -b
```

### Important Options :

* `-u <service>`: Targets a specific systemd service/unit.
* `-n <number>`: Displays the specified number of recent log entries.
* `-f`: Follows the logs live and displays new entries in real-time.
* `-p err`: Filters the logs to show error-priority messages.
* `--no-pager`: Prints the output directly in the terminal instead of opening a pager.

## Task 4: Important Cheat Sheet Commands to Practice

These are some useful Linux commands for checking system resources, network information, and active connections.

```bash
# 1. Check disk space in human-readable format
df -h

# 2. Check RAM / Memory usage
free -h

# 3. Check active listening ports and sockets
# ss is a modern replacement for netstat
ss -tuln

# 4. View network interface and IP address details
ip a
```

### Quick Explanation :

| Command    | Purpose                                                 |
| :--------- | :------------------------------------------------------ |
| `df -h`    | Shows disk space usage in a human-readable format.      |
| `free -h`  | Shows RAM and swap memory usage.                        |
| `ss -tuln` | Shows listening TCP/UDP ports and sockets.              |
| `ip a`     | Displays network interfaces and IP address information. |
